# Product

## Register

brand

## Platform

web

## Users

First-time GitHub visitors evaluating whether the Networked Thinking companion vault is relevant to how they learn, write, and make decisions. They need to understand quickly that this repository is a working knowledge system rather than a collection of empty templates.

## Product Purpose

Present the Networked Thinking Obsidian vault as the practical implementation of the book's methodology. The README should help visitors recognize the value of connected notes, understand what the repository contains, and decide whether to inspect, download, or adopt the vault.

## Brand Personality

Confident, human, and evidence-led. The repository should feel considered and trustworthy, with the density of a real working system rather than the polish or hype of a generic productivity product.

## Anti-references

Generic AI and SaaS marketing imagery, abstract network decoration with no relationship to the real vault, excessive interface chrome, and banner treatments that prioritize slogans over the knowledge graph itself.

## Design Principles

1. **Show the system working.** Use real artifacts from an active vault as evidence of the methodology.
2. **Density should remain legible.** Complexity is meaningful here, but hierarchy and cropping must make it inviting rather than noisy.
3. **The graph is the subject.** Branding and explanatory copy should orient the viewer without obscuring the network.
4. **Connect the repository to the wider identity.** Reuse the companion site's established visual language where it strengthens recognition.
5. **Design for the GitHub reading context.** The asset must remain clear at responsive README widths and across common display densities.

## Accessibility & Inclusion

Meet WCAG 2.2 AA for all text embedded in visual assets. Keep essential repository information available as live README text, provide descriptive alt text, and avoid relying on node color alone to explain meaning.
